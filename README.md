# 🏫 NDKY 招生顾问 Agent

> **基于 RAG + Tool Calling 的高校智能招生咨询系统**
>
> 面向高校招生咨询场景，让大模型通过自主调度多个工具（知识库检索、分数线查询、志愿分档、学校信息），结合考生画像给出个性化招生建议。

---

## 一、项目背景

传统高校招生咨询存在几个痛点：

- 招生政策、专业介绍分散在历年问答和招生章程里，考生要翻很久
- 历年录取分数是结构化数据，普通 RAG 问答机器人查不了、也算不了
- 考生问"我560分能报什么"，需要**结合分数做判断**，不是简单检索能回答的
- 普通问答机器人无法结合考生的省份、分数、意向专业给出个性化建议

因此设计了 NDKY 招生顾问 Agent：考生用自然语言说一句"浙江560分，想学计算机，能报哪些专业"，Agent 自动理解需求、选择并调用工具、整合结果、生成建议。

---

## 二、项目特点：从 RAG 到 Agent

| | 传统 RAG 问答 | 本系统（Agent） |
|---|---|---|
| 流程 | 用户问题 → 知识库检索 → LLM 回答 | 用户问题 → Agent 任务判断 → 工具选择 → 数据查询/知识检索 → 结果整合 → LLM 生成 |
| 能力边界 | 只能回答知识库文档里有的事实 | 既能查政策，也能查分数线、算冲稳保、结合考生画像给建议 |
| 工具使用 | 固定一条检索链路 | Agent 自主决定调哪个/哪几个工具，可串联多个 |

支持的咨询场景：

- 🔍 招生政策查询（宿舍、转专业、学费、档案）
- 📊 历年录取分数查询（最高/最低/平均分、位次）
- 🎯 志愿分档推荐（冲/稳/保/偏险）
- 🏫 学校基本信息（校区、性质、电话）
- 💬 多轮追问（"那软件工程呢""那学费呢"自动带上文）

## 四、Agent 工作流程

以"我浙江560分报计算机怎么样？"为例：

**Step 1 · 任务理解**
Agent 结合考生画像，识别出结构化意图：
```json
{ "province": "浙江", "score": 560, "target": "计算机" }
```

**Step 2 · 工具选择**
Agent 判断需要：
- `recommend_majors`（看560分能报哪些专业）
- `query_admission_score`（查计算机历年分数）
- `search_knowledge`（查计算机选科要求、学费）

**Step 3 · 工具执行**
- 志愿分档工具：读 `scores.json`，对比2025年各专业最低分，分出保底/稳妥/冲刺/偏险
- 分数查询工具：返回计算机近三年最高/最低/平均分、位次
- 知识库检索：bge 向量 + jieba BM25 双路召回，RRF 融合

**Step 4 · 生成回答**
LLM 综合用户信息、工具结果、检索资料，输出：专业建议、分数参考、学费信息、数据来源。

## 五、技术架构

### Agent 层
- Python · 手写 ReAct 循环（不依赖 LangChain / LangGraph）
- OpenAI function calling 协议（DeepSeek）
- 多轮状态管理：每轮收敛成干净 [user, assistant] 对，保留最近6轮
- 考生画像状态：前端维护省份/分数/意向，每轮注入 system prompt

### RAG 检索层（Hybrid Retrieval）
- **Dense Retrieval**：bge-small-zh 中文语义向量，做语义匹配
- **Sparse Retrieval**：BM25（jieba 中文分词），做关键词精确匹配
- **RRF 融合**：`score = Σ 1/(k+rank)`，融合两路结果
- 检索效果：Top-4 召回率 **89.5%**（纯向量仅 63.2%，提升 26.3pp）

## 六、工具设计

### 1. `search_knowledge`
- 用途：招生政策、学校信息、宿舍、转专业等知识库问答
- 输入：`query`（检索关键词）
- 输出：相关历史咨询片段

### 2. `query_admission_score`
- 用途：查某专业历年录取分数
- 输入：`major`（专业名）、`province`（省份，默认浙江）
- 输出：历年最高/最低/平均分、位次

### 3. `recommend_majors`
- 用途：按考生分数推荐专业，分冲/稳/保
- 输入：`province`、`score`、`rank`（可选）
- 输出：各专业分档列表

### 4. `school_info`
- 用途：学校硬事实（校区、代码、电话）
- 输入：`topic`（可选）
- 输出：基于2026招生章程的学校基本信息

## 十、项目亮点（面试版）

1. **从 RAG 升级到 Agent**：不止实现知识检索，还通过 function calling 让模型自主调度工具，完成专业推荐、录取分析等需要"计算+判断"的复杂任务。
2. **混合检索提升召回**：bge 语义向量 + BM25 关键词检索，RRF 融合，Top-4 召回率从 63.2% 提升到 89.5%。
3. **数据与模型解耦**：确定性计算（分数对比、分档）交给 Python 工具完成，避免 LLM 直接算数字造成幻觉。
4. **可解释回答**：回答末尾自动附数据来源链接，用户可点开招生网原文核对，招生场景下可信度高。
